Optimizing WebGL Morph Targets in glTF Shaders

Evaluating morph targets on the web can quickly saturate GPU resources due to strict vertex attribute limits and memory bandwidth bottlenecks. In glTF workflows, shifting morph target computation to fragment shaders or texture-driven pipelines unlocks scalable facial animation and character deformation. This article outlines the primary architectural and rendering optimizations used to accelerate morph target evaluation in WebGL, focusing on texture packaging, pre-accumulation passes, sparsity encoding, and runtime weight pruning.

Texture-Based Storage (DataTextures)

WebGL implementations face hardware limits on vertex attributes (typically 16 generic attributes), restricting vertex-based morphing to only a few targets. Encoding morph target deltas (positions, normals, and tangents) into floating-point textures (gl.FLOAT or gl.HALF_FLOAT) circumvents attribute limits.

By flattening delta vectors into 2D textures or TEXTURE_2D_ARRAY instances, the fragment pipeline accesses hundreds of morph targets via texture fetches rather than dedicated attribute buffers. A 2D array texture is preferred over a standard texture atlas because it eliminates edge-bleeding artifacts between targets and removes the need for manual UV coordinate clamping.

Pre-Accumulation Offscreen Passes

Evaluating morph target weights directly within the primary mesh material shader introduces excessive texture fetches per fragment, severely degrading fill rate.

A high-performance pattern uses an offscreen accumulation pass:

  1. Render a single pass into a Framebuffer Object (FBO) containing a displacement texture representing the cumulative deltas for the current frame.
  2. The fragment shader loops through active morph targets, sampling each slice of the morph texture array, multiplying it by the respective target weight, and accumulating the result.
  3. The main forward or deferred rendering pass samples this single pre-accumulated displacement texture once, treating it as an aggregated delta buffer.

This decouples the scene's complex lighting computations from the heavy multi-texture sampling loops required for morph evaluation.

Sparse Delta Encoding

Most morph targets, particularly facial expressions in glTF models, deform only a small subset of the total mesh vertices. Storing dense textures for every target wastes memory bandwidth and texture cache capacity.

Optimized pipelines implement sparse morph target packing:

  • Index-Value Packing: Only store vertices with displacements exceeding a specific error tolerance.
  • Coordinate Remapping: Pack active vertices contiguously in the texture and maintain a compact lookup table, reducing the dimensions of the morph target texture.
  • Cache Coherency: Arrange texels according to vertex spatial locality or draw call order rather than raw index order, maximizing GPU texture cache hits during rasterization.

Active Target Pruning and Weight Thresholding

Uniform arrays containing morph weights often contain values that are zero or near-zero. Performing texture lookups and vector math on negligible weights wastes GPU cycles.

  • Threshold Clamping: Introduce an epsilon check (\(\epsilon < 0.001\)) on the CPU or in a dispatch uniform.
  • Dynamic Index Buffers: Compile a dynamic list of active morph targets per frame. Only bind and pass active slice indices and weights to the fragment shader, truncating the accumulation loop early.

Precision Downscaling with Half-Float Formats

While position deltas often demand high precision, using 32-bit floating-point textures (RGBA32F) places a heavy burden on memory bandwidth.

Converting target deltas to 16-bit half-floats (RGBA16F) reduces bandwidth consumption by 50% and improves texture cache residency on mobile and integrated GPUs. For positions, store the deltas as normalized values relative to the mesh’s bounding box, reconstructing absolute deltas in the shader using a single uniform scale factor. Normal and tangent deltas can be packed using octahedron encoding, fitting directional vectors into two 16-bit channels instead of three or four full floats.
