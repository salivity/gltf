Costs of Rendering Dispersive glTF Materials

Rendering dispersive transmissive materials in glTF entails simulating wavelength-dependent light refraction through transparent volumes, which introduces significant computational overhead. This article breaks down the primary computational costs involved, including increased ray and sample counts, memory bandwidth bottlenecks from multi-pass framebuffers, shader divergence on modern GPUs, and the compounded rendering burden when paired with volumetric absorption.

Multi-Wavelength Ray Sampling and ALU Overhead

In standard transmissive rendering, a single refraction vector is calculated based on an index of refraction (IOR). Dispersion—specified in glTF via the KHR_materials_dispersion extension alongside KHR_materials_transmission and KHR_materials_volume—causes the IOR to vary across the visible light spectrum.

To model this physically, the renderer must trace separate light paths for different wavelengths.

  • Real-time rasterization: Shaders approximate dispersion by splitting the refracted ray into discrete color channels (typically Red, Green, and Blue). This triples the required arithmetic logic unit (ALU) operations for refraction math, Fresnel calculations, and subsequent vector transformations.
  • Path tracing: Accurate continuous dispersion requires spectral rendering or stochastic wavelength sampling per path. Stochastic sampling increases variance, meaning renderers require significantly higher samples-per-pixel (SPP) to resolve chromatic noise, directly scaling execution time.

Texture Fetch and Memory Bandwidth Penalties

Real-time render engines typically implement transmission via screen-space techniques using an opaque scene color buffer (often referred to as a transmission pass).

When dispersion is active:

  • Multiple Texture Lookups: Instead of a single texture fetch from the background or transmission copy, the shader must sample the background buffer multiple times along the dispersed chromatic path.
  • Roughness Sampling: If the material also utilizes KHR_materials_roughness, the engine must read from downsampled mipmap chains to simulate blurry transmission. Performing multiple wide-offset dependent texture fetches across varying mip levels breaks texture cache locality, resulting in high L1/L2 cache miss rates and memory bandwidth saturation.

GPU Warp Divergence

Modern GPUs execute threads in synchronized groups (warps or wavefronts). Transmissive dispersive surfaces introduce two forms of execution divergence:

  1. Dynamic Branching: Pixels with varying material properties (e.g., partial transmission textures or complex geometry edges) branch differently through expensive dispersion logic, forcing threads in the same warp to serialize.
  2. Ray Divergence in Hardware Ray Tracing: In hardware-accelerated ray tracing (DirectX Raytracing or Vulkan Ray Tracing), tracing dispersed rays sends secondary rays in slightly divergent trajectories. This causes spatial incoherence in the bounding volume hierarchy (BVH) traversal, diminishing the efficiency of ray-tracing hardware cores.

Compounding Volumetric Absorption Calculations

glTF handles dispersion within volumetric geometry via KHR_materials_volume. Computing physical light transmission requires evaluating the Beer-Lambert law, which attenuates light exponentially based on path length and attenuation color.

When dispersion separates light into distinct spectral paths, the renderer must compute separate path lengths and exponential absorption factors for each sample. This multiplies transcendental math instructions (exp calls) and complicates inner shader loops, driving up the overall register pressure and reducing GPU occupancy.
