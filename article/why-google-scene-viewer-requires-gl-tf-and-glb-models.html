Why Google Scene Viewer Requires glTF and GLB Models

Google Scene Viewer requires glTF (GL Transmission Format) and its binary counterpart, GLB, because they provide the ideal balance of compact file size, rapid loading, and standardized 3D rendering for web-based augmented reality. Designed specifically for efficient transmission over the internet, glTF/GLB streamlines how Android devices unpack, render, and anchor 3D assets in real-world environments without requiring dedicated apps or heavy processing overhead.

The Standard for Web-Based 3D Transmission

Developed by the Khronos Group, glTF was engineered from the ground up to be the "JPEG of 3D." Unlike authoring formats like FBX or OBJ—which are designed for editing software and contain redundant metadata—glTF is a runtime transmission format. It discards unnecessary production data and focuses strictly on what the rendering engine needs to display the model.

Direct-to-GPU Architecture

Traditional 3D formats require extensive parsing and conversion before a mobile GPU can read them, leading to latency and high memory usage. glTF structures its data—including vertex buffers, indices, and animations—so that it can be loaded directly into the GPU's memory with minimal client-side decoding. For web-based AR via Scene Viewer, this direct pipeline ensures near-instantaneous transitions from a web browser to an augmented reality view.

All-in-One Packaging with GLB

While standard glTF references external files for textures and binary buffers, GLB encapsulates the entire 3D asset—geometry, shaders, animation data, and image textures—into a single binary file. This single-container approach offers major benefits for web AR:

  • Fewer Network Requests: Consolidating assets into one file eliminates multiple HTTP requests, significantly decreasing load times on mobile networks.
  • Simplified Delivery: Web developers can host and serve a single asset without risking broken file paths for textures or materials.

Standardized Physically Based Rendering (PBR)

Realism in augmented reality depends on how virtual objects interact with real-world lighting. Google Scene Viewer uses Physically Based Rendering (PBR) materials defined by the glTF 2.0 specification. This standard defines parameters like roughness, metallic properties, and normal maps uniformly. Because these material definitions are standardized, 3D models look consistent and react realistically to environmental lighting estimated by ARCore across various Android hardware.

Native ARCore and Android Integration

Google built Scene Viewer on top of Android’s rendering pipelines, such as the Filament real-time PBR engine. Filament natively supports glTF/GLB, allowing Scene Viewer to execute AR experiences with predictable performance, stable frame rates, and low battery consumption. By enforcing a single, optimized format, Google avoids the fragmentation, rendering bugs, and performance bottlenecks associated with supporting legacy 3D file types.
