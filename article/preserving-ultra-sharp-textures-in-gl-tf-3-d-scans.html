Preserving Ultra-Sharp Textures in glTF 3D Scans

Digitizing cultural heritage sites and artifacts produces dense photogrammetry scans with microscopic surface information that often degrades during real-time web delivery. This article outlines the core technical workflows—ranging from advanced texture compression and multi-material partitioning to micro-detail tiling and optimal mipmap filtering—used to preserve ultra-sharp texture details on massive heritage assets within the glTF 2.0 framework without overloading client-side memory.

Converting UDIMs to Multi-Material Layouts

Standard glTF does not natively support single-material UDIM (U-Dimension) arrays. To preserve the extreme pixel density of large heritage photogrammetry (such as a 16K or 32K composite surface) without exceeding hardware texture limits:

  • Segment Meshes by Material: Split the master asset into logical geometric sub-meshes based on UV tiles. Assign each tile its own standard PBR material equipped with an independent 4K texture.
  • Keep Resolution Uniform: Distribute UV space based on visual significance. Carvings, inscriptions, and high-erosion zones should receive higher texel density than flat structural areas.
  • Maintain Vertex Continuity: Ensure boundary vertices between separated UV shells retain identical normals and positions to avoid visible seams under dynamic lighting.

Utilizing KTX2 with UASTC Compression

Traditional image formats like JPEG and PNG consume excessive GPU VRAM because they must be fully uncompressed into memory. While the KHR_texture_basisu glTF extension provides dramatic compression via Basis Universal, selecting the correct mode is critical for heritage preservation:

  • Use UASTC Instead of ETC1S: While ETC1S offers tiny file sizes, it aggressively blurs sharp edges and destroys normal map vectors. UASTC (Universal ASTC) provides high-fidelity, high-frequency detail preservation essential for stone grain, canvas weave, and fine cracks.
  • Apply RDO (Rate Distortion Optimization): Use RDO encoding on UASTC files to shrink file transfer size over the network while retaining near-lossless surface clarity.
  • Channel Independence: Encode normal maps using dedicated two-channel formats (such as RG with derived Z) within the KTX2 container to prevent cross-channel compression artifacts.

Implementing Detail Normal Maps

Baking millions of micro-polygons directly into a single massive normal map often exceeds web runtime limits. Layering macro and micro maps overcomes this barrier:

  • Macro Geometry Baking: Bake the low-frequency contours and unique cracks into a standard resolution (2K or 4K) primary normal map.
  • Tiling Micro-Normal Maps: Use the KHR_texture_transform extension to apply a high-frequency, tileable micro-detail normal map over the primary surface. This simulates fine stone porosity, tool marks, or wood grains at extreme close-up distances without requiring gigabytes of unique texture memory.

Optimizing Mipmap Generation

Standard box-filter mipmapping tends to soften sharp crevices, high-contrast pigments, and chisel marks when viewed at intermediate distances.

  • Use Sharpened Downsampling: Generate custom mipmaps prior to glTF packaging using Kaiser, Lanczos, or Mitchell-Netravali filtering instead of bilinear downsampling.
  • Preserve Normal Vector Lengths: When downsampling normal maps, normalize the vector lengths at each mip level to prevent the artifact from flattening out visually as the camera retreats.

Implementing Chunked Mesh LODs

Loading full-fidelity textures across an entire architectural site simultaneously leads to browser crashes.

  • Hierarchical Chunking: Partition large heritage assets (e.g., temples, statues, ruins) into spatial bounding boxes.
  • Progressive Streaming: Implement the MSFT_lod extension or external hierarchical 3D Tiles / glTF streaming architectures. This ensures ultra-high-resolution textures are loaded dynamically only for the specific segments occupying the viewer's immediate field of view, keeping memory consumption stable.
