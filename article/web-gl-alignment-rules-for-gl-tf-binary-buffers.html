WebGL Alignment Rules for glTF Binary Buffers

This article provides an overview of how memory alignment specifications in the glTF 2.0 format correspond directly with WebGL’s buffer consumption requirements. Efficiently rendering 3D assets requires feeding binary data from .bin files directly to the GPU without CPU-side repacking. By understanding the alignment rules governing component types, buffer views, accessor offsets, and byte strides, developers can achieve zero-copy data uploads between glTF payloads and WebGL buffers.

The 4-Byte Boundary Rule for BufferViews

The primary alignment rule shared between glTF and WebGL centers on the 4-byte boundary. In the glTF 2.0 specification, every bufferView object defining a segment of a binary payload must have its byteOffset aligned to a multiple of 4.

This directly matches WebGL’s native expectations. WebGL contexts allocate memory using underlying graphics drivers that typically expect buffer objects bound to targets like gl.ARRAY_BUFFER or gl.ELEMENT_ARRAY_BUFFER to begin on at least 4-byte boundaries. By adhering to this rule, an entire chunk of a glTF binary file can be passed directly to gl.bufferData() or gl.bufferSubData() via an ArrayBuffer slice without triggering misaligned memory exceptions.

Accessor Byte Offsets and Component Sizes

Within a bufferView, individual attributes (such as positions, normals, or texture coordinates) are defined by accessor objects. The glTF specification dictates that an accessor's byteOffset must be a multiple of the size of its componentType:

  • 1 Byte: 5120 (BYTE), 5121 (UNSIGNED_BYTE) requires a 1-byte alignment.
  • 2 Bytes: 5122 (SHORT), 5123 (UNSIGNED_SHORT) requires a 2-byte alignment.
  • 4 Bytes: 5125 (UNSIGNED_INT), 5126 (FLOAT) requires a 4-byte alignment.

In WebGL, the gl.vertexAttribPointer(index, size, type, normalized, stride, offset) call requires the offset parameter to align precisely with the component type passed to type. Attempting to configure an attribute pointer with an offset that does not align with the byte size of the attribute's underlying data type causes a gl.INVALID_OPERATION error in WebGL implementations.

Interleaved Data and Byte Stride Constraints

When vertex attributes are interleaved inside a single bufferView, both glTF and WebGL impose strict stride rules:

  1. Multiple of 4: glTF requires the byteStride of a bufferView to be a multiple of 4, ranging from 4 to 252 bytes.
  2. Attribute Size Divisibility: The stride must also be a multiple of the size of the largest component type in the interleaved data structure.

This matches the stride argument in WebGL's gl.vertexAttribPointer(). Because WebGL hardware reads vertex attribute blocks sequentially from GPU memory, keeping strides at 4-byte multiples prevents unaligned 32-bit reads on mobile and desktop GPU architectures, eliminating pipeline stalls.

Index Buffers (ELEMENT_ARRAY_BUFFER) Alignment

For indexed geometry, glTF specifies index components as UNSIGNED_BYTE, UNSIGNED_SHORT, or UNSIGNED_INT.

When binding an index accessor to gl.ELEMENT_ARRAY_BUFFER and calling gl.drawElements(mode, count, type, offset):

  • The offset must be aligned to the index component size (2 bytes for UNSIGNED_SHORT, 4 bytes for UNSIGNED_INT).
  • Because glTF enforces that all bufferView offsets are multiples of 4, index data naturally fulfills WebGL’s offset alignment requirements, provided the accessor offset within that view satisfies the 2-byte or 4-byte constraint.

JavaScript TypedArray Alignment in the Browser

WebGL runs within JavaScript, where typed views (Float32Array, Uint16Array, Uint32Array) represent binary memory buffers. The JavaScript engine strictly enforces that any typed array initialized over an ArrayBuffer with an offset must have its byte offset be an exact multiple of the element size (e.g., new Float32Array(buffer, byteOffset) throws a RangeError if byteOffset % 4 !== 0).

Because glTF aligns every 4-byte attribute accessor to a 4-byte boundary relative to both the buffer start and the buffer view, WebGL applications can instantiate JavaScript typed arrays over glTF binary buffers instantly, enabling direct, high-performance data transfers to the GPU.
